A análise da pasta "bot-ia" (baseada nos arquivos JavaScript fornecidos, como trade-manager.js, monitoring.js e outros relacionados) mostra que o processo de execução de trades é centralizado em dois arquivos principais:

### Fluxo Geral
1. **Verificação das Estratégias**: 
   - Isso ocorre no arquivo **monitoring.js**, no método `checkRulesForTrading(translatedRules, forcedPrice = null)`.
   - Aqui, as regras da estratégia (configurações traduzidas para JSON) são avaliadas em tempo real com base nos dados de mercado (preços de ticks).
   - Quando todas as regras de um grupo (AND logic dentro do grupo, OR entre grupos) são atendidas (`anyGroupSatisfied = true`), o sistema identifica o grupo satisfeito (`satisfiedGroupId`) e captura previsões dinâmicas se aplicável (ex.: dígitos específicos como "over 5").
   - Em seguida, chama `executeTradeBasedOnRules(satisfiedGroupId, capturedPrediction, forcedEntryPrice)` para iniciar o trade.

2. **Execução do Trade**:
   - O trade propriamente dito é executado no arquivo **trade-manager.js**, no método `executeTrade(entryPrice, satisfiedGroupId = null, bypassTradeLimit = false)`.
   - Esse método roteia a execução com base no modo atual (SIMULACAO, REAL ou VIRTUAL):
     - Para simulação: Chama `executeSimulatedTrade(entryPrice, bypassTradeLimit)`.
     - Para real/virtual: Chama `executeRealTrade(entryPrice, bypassTradeLimit, options)`.
   - Dentro de `executeRealTrade`, ocorre a compra do contrato via API (Deriv), usando `api.sendRequest(buyParams)` para efetivar o trade.
   - Se for modo "BOTH" (múltiplos contratos), roteia para `executeBothTrade(entryPrice, satisfiedGroupId, executionMode)`, que pode chamar `executeBothReal` ou `executeBothSimulated`.

### Detalhes Adicionais
- **Condições para Execução**: As estratégias "batem" em monitoring.js quando `allRulesInGroupSatisfied = true` para pelo menos um grupo. Isso depende de funções como `checkRuleCondition(rule, forcedPrice)` (que usa helpers como formatGenerator para validar regras como RSI, SMA, percentuais, etc.).
- **Outros Arquivos Envolvidos**:
  - **generate-format.js**: Auxilia na formatação e verificação de regras (ex.: `checkRuleCondition`).
  - **TradeContractSelector.js**: Determina contratos para modo "BOTH" quando múltiplos trades são necessários.
  - **cooldown-overlay.js**: Gerencia pausas pós-trade, bloqueando novas execuções até o cooldown acabar.
- **Observações**: Não há um método único chamado "executeTradeAfterMatch", mas o fluxo acima é o equivalente. Se o bot estiver em modo simulação, não há trade real (apenas log/simulação). Para trades reais, requer conexão com Deriv API (em deriv-api.js).
